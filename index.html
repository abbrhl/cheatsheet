Audit & Incident Response • 6 uur totaal

⏰ Tijdmanagement (6 uur totaal)

OpdrachtTijdWat lever je in
Opdracht 1 (W1)180 minAuditrapport
Opdracht 2 (W2)180 minOnderzoeksverslag + E-mail + Aangepaste server + Logboek

Verdeel binnen Opdracht 1:

  • 30 min scans uitvoeren (Nmap, MBSA, etc.)
  • 30 min interviews + firewall-log doorlezen
  • 30 min analyseren + risico's inschatten
  • 90 min auditrapport schrijven

Verdeel binnen Opdracht 2:

  • 45 min onderzoek SRV002 (logs, MySQL, processen)
  • 45 min onderzoeksverslag invullen
  • 30 min e-mail schrijven
  • 60 min server aanpassen + logboek met screenshots

🧰 Tools cheatsheet (ToolBox op desktop SRV001)

ToolWaarvoor gebruiken
NmapOpen poorten scannen — welke services draaien? Welke zijn vreemd?
Microsoft Baseline Security Analyzer (MBSA)Windows config check, missing updates, zwakke wachtwoordbeleid
Sysinternals Suite (Process Explorer, Autoruns, TCPView)Verdachte processen, auto-start programs, actieve netwerkverbindingen
Event ViewerLogins, security events, fouten — zoek op rare tijdstippen
MalwarebytesScan op malware/RATs
WiresharkNetwerkverkeer analyseren (als nodig)

Praktisch: start altijd met Nmap (overzicht) + MBSA (config) + Event Viewer (recente activiteit). Daarna gericht inzoomen.

📋 Opdracht 1 (W1) — Audit van SRV001

Stappenplan

  1. Inloggen als administrator op SRV001
  2. Tools openen uit ToolBox folder
  3. Nmap op localhost/SRV001 → noteer open poorten
  4. MBSA scan → noteer security misconfiguraties
  5. Event Viewer → security log → verdachte logins?
  6. Firewall-log op bureaublad → vreemde verbindingen?
  7. Bestandssysteem check → Downloads folder, share folders, desktop
  8. Interviews (Bijlage 1.1) doorlezen — wat zeggen balie/backoffice/apotheker?
  9. Combineer technische + menselijke bevindingen
  10. Auditrapport invullen (Bijlage 1.2)

Waar je naar kijkt — categorieën

🖥️ Server (SRV001) — technische scan

  • Open poorten (let op rare zoals 464, 636 — wat is hun functie?)
  • Verouderde updates / patches
  • Firewall status (uit/aan)
  • Gedeelde mappen — wie heeft toegang?
  • Verdachte bestanden in Downloads of op desktop
  • Onbekende auto-start programma's
  • Wachtwoordbeleid (te zwak?)
  • Verbindingen met externe netwerken in firewall-log

👥 Mens & beleid (uit interviews)

  • Computers niet vergrendelen
  • Wachtwoorden onder toetsenbord
  • USB-sticks gedeeld
  • Geen logboek bij sluiting
  • Geen beveiligingscamera's
  • Geen beveiligingsbeleid
  • Papieren met persoonsgegevens in prullenbak
  • Geen autorisatieniveaus (iedereen kan alles)
  • Externe IT'er (man van medewerker) — wie heeft toegang?

Risicobeoordeling — gebruik een matrix

Per bevinding bepaal je: Kans × Impact = Risico

NiveauWanneer?
HoogDirect gevaar voor patiëntgegevens (AVG-overtreding mogelijk)
MiddelIndirect risico, vereist combinatie met andere factor
LaagHygiëne-issue, geen directe dreiging

Voorbeelden:

  • Wachtwoord onder toetsenbord + iedereen kan binnenlopen = HOOG
  • Verouderde updates = HOOG (bekende exploits)
  • Geen logboek sluiting = MIDDEL

Auditrapport structuur (Bijlage 1.2)

  1. Inleiding — wie, wat, wanneer, doel audit
  2. Scope — wat is gecontroleerd (SRV001 + interviews)
  3. Methodiek — welke tools en methoden gebruikt
  4. Bevindingen — per categorie (server / netwerk / mens / beleid)
  5. Risicoanalyse — matrix met risiconiveaus
  6. Advies / verbetervoorstellen — concreet & haalbaar
  7. Conclusie

⚠️ Tips voor het advies

  • Maak adviezen SMART: specifiek, meetbaar, haalbaar
  • Niet "verbeter de beveiliging" maar "implementeer wachtwoordbeleid: min. 12 tekens, 90 dagen geldig, MFA verplicht"
  • Per bevinding 1 concreet advies
  • Prioriteer: hoog risico eerst

🚨 Opdracht 2 (W2) — Incident response SRV002 (MySQL datalek)

De 4 vragen die de directie wil beantwoord hebben

VraagHoe vinden?
a. Hoe kon het gebeuren?MySQL config, gebruikersrechten, open poorten, processen, autoruns
b. Wanneer is het gebeurd?MySQL logs, Event Viewer security log, file timestamps
c. Welke informatie?Database inhoud bekijken — welke tabellen, welke velden
d. Hoeveel buitgemaakt?Aantal records in tabellen, log van queries

Onderzoek op SRV002 — stappenplan

  1. Login via RDP
  2. Verdachte processen check (Task Manager / Process Explorer)
  3. MySQL openen — welke databases, welke tabellen, hoeveel records
  4. MySQL logs check (C:\ProgramData\MySQL\...\Data\*.err of query.log)
  5. Event Viewer → Security log → recente logins
  6. Open poorten check (netstat -an of TCPView)
  7. Geïnstalleerde programma's check — staat er een RAT? (TeamViewer, AnyDesk, ngrok, NetCat?)
  8. Autoruns — wat start er automatisch?
  9. Bestandssysteem — verdachte files, downloads
  10. Firewall regels — vreemde uitzonderingen?

Onderzoeksverslag invullen (Bijlage 2.1)

  • Aanleiding — datalek gemeld via forum
  • Onderzoeksvragen — de 4 hierboven
  • Bevindingen — wat heb je gevonden + screenshots/bewijs
  • Kwetsbaarheden + risiconiveau per stuk
  • Tijdlijn — wanneer wat gebeurde
  • Impact — wat is gelekt en hoeveel
  • Conclusie
  • Communicatiematrix — wie informeren over wat

📧 Begeleidende e-mail (Bijlage 2.2) — MOET bevatten:

a. Vervolgstappen om veiligheid op orde te krijgen:

  • Isoleer SRV002 (uit netwerk halen)
  • Wachtwoorden van alle accounts wijzigen (incl. MySQL root)
  • Verwijder kwaadaardige software / RAT tools
  • Patch het systeem
  • Implementeer logging & monitoring
  • Forensisch onderzoek (eventueel extern)

b. Wettelijke verplichtingen — AVG/GDPR datalek:

  • Binnen 72 uur melden bij Autoriteit Persoonsgegevens (AP)
  • Bij hoog risico: betrokkenen informeren (de patiënten)
  • Documenteren van het incident (verplicht register datalekken)
  • Functionaris Gegevensbescherming inschakelen indien aanwezig
  • Medische gegevens = bijzondere persoonsgegevens → extra zware verplichtingen

Communicatiematrix — wie informeren?

WieWatHoe
DirectieVolledige situatie + vervolgstappenE-mail + meeting
SecurityofficerTechnisch detailE-mail + onderzoeksverslag
MedewerkersVoorzichtigheid, wachtwoorden wijzigenE-mail/intern bericht
Betrokkenen (patiënten)Welke data gelekt, wat te doenBrief (verplicht bij hoog risico)
Autoriteit PersoonsgegevensOfficiële meldingOnline formulier AP

🔧 Server aanpassen (Opdracht 2.2) — concrete acties

Op basis van Bijlage 2.3 Kwetsbaarheden (krijg je op papier). Verwacht onderwerpen:

MySQL beveiligen

  • Root wachtwoord wijzigen: ALTER USER 'root'@'localhost' IDENTIFIED BY 'NieuwSterkWW!';
  • Anoniem account verwijderen: DROP USER ''@'localhost';
  • Remote root login uit: zorg dat root alleen vanaf localhost mag
  • Test database verwijderen als die er staat
  • mysql_secure_installation draaien indien beschikbaar

RAT / verdachte tools

  • Check eerst of root/RAT tools geïnstalleerd zijn (Programs and Features, Autoruns, Process Explorer)
  • Verwijder ze via uninstaller + handmatig restanten
  • Daarna pas zelf legitieme remote-access setup doen (als de opdracht dat vraagt)
  • Tip uit eerdere examens: kijk specifiek naar TeamViewer, AnyDesk, NetCat, ngrok, mRemoteNG

Administrator account

  • Lokale Administrator uitschakelen of hernoemen
  • Wachtwoord wijzigen
  • Audit wie er admin rechten heeft

Algemene hardening

  • Windows Firewall aanzetten
  • Onnodige poorten sluiten
  • Windows Updates installeren
  • Defender / antivirus scannen
  • Onnodige services uitschakelen

Logboek (Bijlage 2.4)

Voor elke aanpassing screenshot maken van:

  • Voor de aanpassing
  • Tijdens de aanpassing (welke stap)
  • Na de aanpassing (bewijs dat het is doorgevoerd)

Per actie: tijd, wat gedaan, waarom, screenshot.

🧠 Security concepten — quick reference

CIA Triad

  • Confidentiality — alleen bevoegden mogen erbij (datalek schendt dit)
  • Integrity — data klopt en is niet gemanipuleerd
  • Availability — systemen zijn beschikbaar wanneer nodig

AAA

  • Authentication — wie ben je? (wachtwoord, MFA)
  • Authorization — wat mag je? (rechten/rollen)
  • Accounting — wat heb je gedaan? (logging/auditing)

Vragen die je kunt gebruiken in je analyse

  • Welk CIA-aspect wordt geschonden?
  • Welk AAA-aspect ontbreekt of faalt?
  • Wat is de kans × impact?
  • Welke wetgeving wordt overtreden (AVG)?

✅ Eindchecklist voor inleveren

Opdracht 1:

  • Auditrapport volledig ingevuld
  • Bevindingen onderbouwd met scan-resultaten
  • Risico's geclassificeerd (hoog/middel/laag)
  • Adviezen concreet & haalbaar
  • Conclusie schrijft de kern samen

Opdracht 2:

  • Onderzoeksverslag: alle 4 directie-vragen beantwoord
  • Communicatiematrix ingevuld
  • E-mail: vervolgstappen + AVG verplichtingen genoemd
  • Server aangepast (MySQL wachtwoord, RAT verwijderd, etc.)
  • Logboek met screenshots voor elke aanpassing
  • Tijdlijn van incidenten gedocumenteerd

🎯 Mindset tips

  1. Bevindingen ≠ adviezen — eerst beschrijf je wat je vindt, dan apart wat je adviseert
  2. Onderbouw alles — "het systeem is onveilig" zegt niets. Wel: "Windows Firewall staat uit (gezien in Control Panel), waardoor inkomend verkeer niet wordt gefilterd, risiconiveau HOOG"
  3. AVG noemen waar relevant — medische gegevens = bijzondere persoonsgegevens
  4. Screenshots opslaan als bewijs — niet alleen voor logboek, ook bij audit handig
  5. Maak het kort maar volledig — kwaliteit > kwantiteit
  6. Tijd in de gaten — zet timer per fase
